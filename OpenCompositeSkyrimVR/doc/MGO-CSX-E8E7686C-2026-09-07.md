# MGO CSX compatibility audit — 7 September 2026

Installed binary: `Community Shaders Expanded (CSX)/SKSE/Plugins/CommunityShaders.dll`.
SHA-256: `E8E7686C0B71C80E3F131779FBCBA967BE8773F373A71BFA48C8AB5BADF132C2`.

The existing six exact owner contracts reject this binary. A separate exact
contract is required; version labels are not used as evidence of compatibility.

PE unwind range: RVA `0xF78F0` through `0xF7C76` (exclusive), 902 bytes.
Owner SHA-256: `D210BD48EA46E990368B9521954FB73BCACE1B6352A3FC69B33BEA1A25E0ECA2`.
Accepted indexed-instanced calls: `0xF795C` (7 bytes, `[r10+0xA0]`) and
`0xF7C32` (6 bytes, `[rax+0xA0]`).

Read-only disassembly comparison against the previously validated 1595cffd
binary found 226 instructions in each owner. Besides relocated references,
six immediate operands change thread-local storage offsets and one memory
operand changes a CSX-private structure offset from 0x204 to 0x1FC.
These are not assumed interchangeable: the new contract hashes the complete
new function. OCU does not read or substitute those private offsets.

Manual inspection confirms the same six native draw arguments at both calls.
The first call handles the inactive bridge fast path. The second follows the
suppression branch (`test sil,sil; jne` bypasses the draw), so the adapter does
not force suppressed CSX geometry back into the scene. CSX's own helper calls
and all of its state decisions remain intact.

Validation uses DapaCsxDrawTest against this actual DLL: owner selection,
patch installation/removal, per-byte tamper rejection, argument fixtures,
and WARP/hardware depth-mask/state preservation. Those tests do not establish
live headset behavior or explain the separately observed VD submission stalls.
Live startup, player-mask coverage and headset testing remain required.
