# OCU Custom EyeTracking Test 4.3.7 Hotfix 6

September 12, 2026. Full test package following Hotfix 5.

## Recovery fixes

- SKSE now checks the current motion-vector, main-depth, view, device and context
  identities from a coalesced game-thread maintenance task. Previously the check
  ran about once per second; a recreated depth texture could leave actual
  foveation running at full rate until the next publication, even at the same
  resolution. The new task is requested by the existing 8 ms scheduler and uses
  the latest state when it executes. A blocked game thread queues at most one
  task. Recovery still waits for that task and the next rendering decision.
- Stable resource identities return before AddRef, Release, GetDesc or bridge
  publication. Replacements retain the existing reference ownership and reader
  retirement protocol. Scene-depth ownership checks remain exact; unrelated
  draws cannot become eligible merely because their dimensions match.
- Menu activity is reconciled on the game thread as well as during menu events.
  If the live pause count clears after a close event, the bridge can now clear
  its menu flag without requiring another event. Tracked menus and actual pauses
  continue to protect UI from foveation and DAPA. This adds no Scaleform query.
- Includes the fixed-ring diagnostic timeout correction made after Hotfix 5:
  a fixed profile does not become an amber X solely because 500 ms elapsed.
  New-frame disabled/invalid decisions still clear it; stale tracked gaze still
  expires. The X is not a CSX-version detector.

No additional GPU pass or copy is introduced. There is a more frequent CPU task
and identity check; zero unchanged-resource COM/descriptor work is tested, but
the total Skyrim frame-time impact has not been measured. These changes apply
to the resource/menu bridge used by both runtime VRS and RDM. They do not change
ring rates, DAPA pacing/tuning, controller layouts or the Configurator.

## Components and installation

- Runtime marker: `4.3.7-foveation-debug-hotfix1 / fixed-ring-no-timeout-v1`.
- SKSE marker: `4.3.7-custom-eye-test-hotfix6 / prompt-bridge-refresh-v1 / menu-reconcile-v1`.
- Configurator: `4.3.7-eye-editor-preview6` (unchanged).

Install the full package into the existing OCU MO2 mod while Skyrim is closed,
using the existing Root Builder setup. Back up and restore a customized
`root/opencomposite.ini` to retain saved settings. The public INI keeps Hotfix 5's
Performance default and DAPA tuning. No CSX/OpenShaders DLL is included.
`OCU-Build.json` identifies the exact binaries; `Verify OCU files.py` checks them.
`SHA256SUMS.txt` covers the packaged payload. Earlier Hotfix 5 notes are historical.

## Validation

- Release SKSE build passed. Existing unrelated integer-narrowing warning in
  first-person-node lookup remains.
- 280 production resource-owner/capture/publication checks passed, including
  same-size replacement, every published identity, unavailable/recovery,
  reference balance and retirement while an external reader pins the old set.
  1,250 stable probes performed no COM or descriptor calls.
- 44 production menu-helper checks passed: delayed pause release, nested and
  non-pausing tracked menus, actual pause, missing UI, late bridge/window and
  retry after a failed window-property write.
- Coalesced maintenance test passed: stalled queue, latest-state sampling,
  in-flight requeue suppression and eight concurrent callers.
- 198 existing runtime DAPA menu/cache/scheduler checks passed.
- Native RTX 5070 Ti D3D11/NVAPI scene test passed. The stale-depth fixture
  shades 16,384 pixels per eye at full rate; publishing the replacement restores
  4,864 shader invocations per eye. Its 90-frame stale interval is simulated,
  not a measured recovery delay. Gaze, viewport, resize and session tests passed.

These are reproduced OCU recovery defects; affected gameplay still requires
verification with the loaded DLL markers and actual settings. Test menu
open/close, loading transitions and CSX/upscaler resource recreation.
No new headset, AMD-hardware or game-FPS result is claimed.
