# 4.3.7 Hotfix 1 — rings overlay and runtime routing

Puntloos reported that the eye debug mode showed only its rings, hiding Skyrim,
and that SteamVR started when loading a save through Continue. The uploaded
4.3.7 ZIP is byte-identical to the locally built 4.3.6 ring-debug-v1 package
(SHA256 94e55d5e3a3e78ce7ea15c8f556dde5236684ddb5f7898ae5b2ec406eaf3c7d5).

The corrected ring path uses two eye-only alpha quads over Skyrim's existing
projection, instead of adding a second projection layer. The quad sizes and
positions map back to each eye's actual FOV and orientation. DAPA moves them
to its synthetic eye poses without another texture upload. This avoids the
multi-projection path implicated by the rings-only report; a headset retest
is still required to establish that his runtime renders the result correctly.

OCU also had an independently reproducible routing defect: VRClientCoreFactory
consulted apps-config.json on later calls, even after VR_InitInternal2 had
started an OCU session or an earlier factory call selected OCU. A saved SteamVR
preference could therefore load the alternate runtime into that process.
OCU now pins its client-core selection when its scene initializes or its first
factory request selects OCU. An explicit SteamVR selection before OCU takes
ownership still works. This does not prevent unrelated processes or another
OpenVR DLL from launching SteamVR.

The runtime log now records the caller module for VR_InitInternal2 and
VRClientCoreFactory requests, and the DLL path when a configured alternate
runtime is loaded. Puntloos's actual launch/crash cause is not confirmed: no
failed-run log was attached to the messages inspected. If it persists, collect
OCUnleashedSKSE.log, the Crash Logger report and SteamVR logs/vrserver.txt from
the same failed run; record the active OpenXR runtime and Pimax Play version.

Validation:
- Release runtime build and Configurator publish.
- WARP and hardware D3D11 overlay readbacks; alpha/BGRA, eye-specific quads,
  asymmetric FOV mapping, rotated eye poses, scene/state preservation, DAPA
  image reuse, busy-image recovery and session cleanup. OpenXR calls mocked.
- Exact-source factory regression: the old code fails the late-preference
  and active-OCU cases; the fixed code passes both and preserves explicit
  startup SteamVR selection. Alternative runtime loading mocked.
- Actual built DLL: repeated client-core requests preserve OCU after changing
  an isolated fixture preference to SteamVR. No VR/OpenXR initialization.
- Existing DAPA timing/ownership tests pass. DAPA settings are unchanged.

The SKSE plugin and installed CSX are unchanged. Their component hashes and
individual version markers are recorded in OCU-Build.json. The rebuilt runtime
marker is 4.3.7-custom-eye-test-hotfix1 / ring-debug-v2-quads / runtime-route-v1;
the Configurator title is 4.3.7-test-hotfix1.
