# 4.3.7 Hotfix 2 — startup frame and runtime selection

This test build corrects three reproducible OCU defects:

- After replacing the temporary graphics session, the first submitted eye was copied before the replacement frame began. It was therefore discarded. The deferred wait/begin now happens before either eye is copied, so the first stereo projection contains both eyes from the replacement session.
- Concurrent client-core requests could both read an unselected runtime, then return different OCU and SteamVR cores. Runtime selection and the alternative DLL load are now serialized. A later direct OCU initialization cannot create a competing backend after an alternative core was selected. Recursive selection during the native DLL load returns a defined error; foreign factory calls run outside the selection lock.
- A missing controller device incorrectly mapped to the left-hand index. It now returns an invalid index, preventing state or haptic requests from reaching the other hand.

The first-frame regression compiles production wait/store/submit functions and checks both eye orders, render-permission states, the first complete stereo projection and following frames. It fails before the correction and passes afterward. The runtime-routing regression similarly reproduces the old mixed-core race and covers concurrent selection, preference changes, direct initialization and reentrant calls. The device-routing regression exercises production state and haptic functions, including missing devices and reconnection.

These are local verification results. They do not establish that the persistent Pimax Dream Air/Sboys3 controller failure is resolved on hardware. The reported OpenXR session remained SYNCHRONIZED with inactive controller actions; its supplied SteamVR logs covered different sessions. A matching headset test must show visibility/focus and active controllers. No forced focus, fabricated input, or guessed controller profile is used.

## Build and verification

Runtime and Configurator are rebuilt as 4.3.7 Hotfix 2. The package retains the existing SKSE plugin, Keyboard Studio, CSX compatibility path and user settings. Existing input recovery and DAPA timing checks are run alongside the startup/routing regressions. Tests against the built DLL exercise concurrent client-core calls without starting OpenXR or SteamVR.

The runtime now writes its process ID, UTC timestamp, executable/DLL path and configured runtime paths at startup. These values are captured inside the game process, where its MO2 environment applies. The subsequently reported OpenXR runtime name remains the evidence for the runtime actually selected.

The package's OCU-Build.json identifies each component and its SHA-256. SHA256SUMS.txt covers the payload. The included Verify OCU files.py checks package components; Tools/ControllerDiagnostics captures current-session runtime logs without changing settings.
